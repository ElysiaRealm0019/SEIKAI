# 训练数据生成逻辑解析

> 对应脚本：`Latest_Development/AI/AIControl/collect_training_data.py`（v6）
> 关联：`offset_anchors.py`、`merge_anchors.py`、`fit_mlp.py`、`retrain_all.py`
> 闪烁修复的完整数据见 `MMDToonShader_Full_AI_使用文档.md` 9.5。

---

## 1. 目标与核心挑战

AI 渲染要的是「给定光向，输出三个阴影/曝光参数」这一函数。训练它的**标签**从哪来？
本项目不走「写个损失函数让优化器自己找最优参数」那条路（v4 曾用 12 维风格统计量 +
Nelder-Mead，因欠定、ShadowLocation 学不到信号而被放弃），而是：

> **让美术在若干光照角度下手动调好参数，录成锚点；机器负责在锚点之间造出一个
> 处处有定义、且尽量平滑的标签场。**

核心挑战不在「插值」本身，而在**锚点是人手逐帧校的，彼此并不一致**：同一条甩拍相邻
帧、不同甩拍相近光向，同一个参数可以差很多。插值器必须决定「信谁」——而这个决定直接
决定上机后阴影边界会不会抖。

---

## 2. 光照空间采样

### 2.1 只采光，不采相机

本项目设计为「相机不动、正对角色正面，光源动」。因此相机方向 `V_cam` 是**每帧一个
常量**（物体中心 → 相机），不是逐像素视线向量；采样管线只生成单位光向 `L`。

`V_cam` 必须与 UE 导出器逐行写入锚点表的 `VcamX/Y/Z`、shader 端
`GetWorldCameraOrigin − GetObjectWorldPosition` 三处严格一致 —— 否则整张特征空间错位，
而这件事不会报任何错。

### 2.2 斐波那契球面采样 (Fibonacci Sphere)

要在三维空间里训练光照，需要球面上近似均匀的点。用经纬度随机采样会让两极（正顶光、
正底光）密集、赤道稀疏。斐波那契球面利用黄金分割生成各向同性的 N 个点，避免模型对
某个光向区域过拟合。

> 注：采样只影响 MLP 拟合标签场的采样密度，不影响标签本身的定义。

## 3. 标签的构造

### 3.1 锚点表结构

`anchors.csv` 每行 = 一个光向下的理想参数，由 UE 插件 `UE_MMDAnchorRecorder` 导出：

```
LdotV,L_up,L_right,ShadowSmooth,ShadowLocation,ExposureScale,VcamX,VcamY,VcamZ,note
```

| 列 | 含义 |
|---|---|
| `LdotV` | `dot(L, V_cam)`，光的前后分量（>0 顺光，<0 逆光） |
| `L_up` | `L.z`，光源高度 |
| `L_right` | `dot(L, Right)`，`Right = cross(Z_up, V_cam)`，光在角色左右哪一侧 |
| 后三列 | 该光向下理想的 `SS` / `SL` / `EX` |
| `VcamX/Y/Z` | **生成这一行时导出器实际用的 `V_cam`**（逐行记录） |
| `note` | `<序列名> frame=<帧号>`，必须是最后一列 |

- **为什么有 `L_right`**：相机固定正对角色正面时，光向被限制在一个圆上，前两个特征
  无法区分正左前光与正右前光。第三维取回的只是符号，而那正是区分左右所需的全部信息。
- **特征空间与光向的换算**：`F = M L`，其中 M 的三行是 `(V_cam, Z_up, Right)`。V_cam 非
  水平时 M 的基向量不正交，`LdotV²+L_up²+L_right²` 不恒为 1（这是正常现象，不是 bug）。

### 3.2 默认插值器：IDW（反距离加权，power = 2）

`ideal_params()` 在三维特征空间里对锚点做 IDW：

```
w_i = 1 / d_i² ,  p = Σ w_i · y_i / Σ w_i
```

性质：处处有定义、在锚点处精确通过。**「精确通过」正是它的问题** —— 见 3.4。

### 3.3 去偏置：`offset_anchors.py`（推荐先做）

每条甩拍相对「其余拍摄建成的场」有一个系统性残差（实测中位：`正面-0度` 的 SS −0.38、
`正面-65度` 的 SL +0.54）。脚本按拍摄估计并扣掉这个常数偏置：

- 跨拍摄 |ΔSS| 中位 0.310 → 0.180；
- 逐帧边界抖动 >0.5°/帧 的比例 13.96% → 10.50%，且 u 极差**上升**（没有把场抹平）。

**代价**：扣偏置等于用「跨拍摄共识」替换美术逐条拍摄给的绝对值。若某些差异是有意的
艺术选择（例如逆光特意压出剪影），这么做会把画面变平。因此脚本默认只报告、不写文件；
`retrain_all.py --take-offset` 才启用。本仓库为同类事烧过一次（EX 死黑兜底），故谨慎。

### 3.4 光滑标签：`--smooth-order`（推荐）

去偏置之后仍有无法消除的锚点矛盾。IDW 精确穿过每一个锚点，会在矛盾点之间形成**脊**，
光扫时表现为边界逐帧抖动。替代方案是用**低阶球谐最小二乘**拟合一个全局光滑场：

```
B = 实球谐基(L, order)                 # 列数 (order+1)²
coef = solve(BᵀB + ridge·I, BᵀY)       # ridge 正则，默认 1e-6
p(F) = B(M⁻¹F) · coef
```

- 全局 C∞，没有脊，因此没有逐帧抖动；
- **不再精确穿点**，锚点残差中位约 0.15（15/75 行 >0.3）；
- **阶数必须低**：3 阶实测 0.58% >0.5°/帧；4 阶以上出现龙格式震荡，抖动回升到 20~36%。

| 口径 | 边界抖 >0.5°/帧 | u 极差 | 备注 |
|---|---|---|---|
| IDW（power 2，不合并） | 11.4% | 0.466 | 基线 |
| 合并同光向重复锚点（4°） | 11.4% | 0.466 | 几乎无效（只合并 11/75 行） |
| 扣拍摄偏置 | 10.5% | 0.647 | 有效但不彻底，且改美术值 |
| **扣偏置 + SH L3 光滑** | **0.0%** | 0.489 | 当前推荐 |
| 纯 SH L3（不去偏置） | 0.6% | 0.79 | 残差中位 0.23 |

## 4. 校验与防呆（宁可直接失败）

| 检查 | 目的 |
|---|---|
| `resolve_vcam_from_anchors()` | 锚点表逐行 `V_cam` 必须齐全、一致、与配置常量相符；不符即中止 |
| `validate_param_bounds()` | 锚点参数必须落在 `PARAM_BOUNDS` 内；越界即中止（clip 会静默削顶） |
| `offset_anchors.py` 夹回 | 扣偏置后可能越界（SS 到 −0.058），显式夹回并打印数量，而非静默 |
| `fit_mlp` 留出 R² | 切 20% holdout，退化判据用留出 R²；同时打印 IDW/光滑基线作管线哨兵 |

`V_cam` 逐行记录的理由：同一文件里可能混着不同批次的导出。真踩过一次 —— 25 个锚点里
15 个用了错误的参考原点（导出时灯被选中），全表一个值分不出这种「混」。

---

## 5. 工程细节：多进程与 `OMP_NUM_THREADS=1`

`collect_training_data.py` 支持 `ProcessPoolExecutor` 并行。但 Numpy/Sklearn 底层的
OpenBLAS/MKL 默认自己开多线程，与 Python 多进程叠加会造成线程爆炸与上下文切换地狱。
脚本顶部注入 `OMP_NUM_THREADS=1`（及 MKL/OPENBLAS/NUMEXPR）把底层库摁成单线程。

> **光滑模式强制单进程**：球谐系数是父进程内存里的对象，子进程重新 import 模块只会拿到
> IDW。单进程跑 500 条样本只需 0.1s，没必要并行。

## 6. 输出

- `training_data.csv`：500 条 `(LdotV, L_up, L_right, SS, SL, EX)`，供 `fit_mlp.py` 训练；
